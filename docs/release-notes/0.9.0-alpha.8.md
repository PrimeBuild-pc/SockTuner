# SockTuner 0.9.0-alpha.8

## Changes

- Separate optional driver-store cleanup from latency diagnosis. Find unused older versions across
  driver families, retain the newest version and every version bound to any device, and let the
  user choose Apply, dismissal or manual cleanup with Driver Store Explorer (RAPR).
- Revalidate eligibility in the elevated worker before removal. Never pass `/uninstall` or `/force`.
  Show an explicit warning that package removal has no automatic undo.
- Measure ICMP latency while ETW driver capture is active, after an initial baseline. Require
  repeated concurrent evidence before offering interrupt-affinity or ancillary-device-disable
  actions; isolated spikes and inconclusive samples cannot enable those actions.
- Protect display/GPU, storage, system/chipset, network, input and unknown device classes from
  host-diagnostics disable actions. Every change remains user-initiated and consent/elevation gated.
- Fix a WPF startup deadlock that prevented elevated workers from consuming pipe requests.
- Fix single-file packaging so TraceEvent can locate its extracted native kernel-trace dependency,
  and preserve driver filename extensions when mapping ETW modules to devices.
- Include the five reviewed dependency updates, recovered #49 research and refreshed README gallery.

## Limits and safety

Repeated activity and jitter are an observation, not proof that a driver caused a network problem.
This check does not create a throughput load; compare before/after under the same workload. Missing
replies, an occupied kernel trace session, incomplete inventory or ambiguous device mapping produce
an inconclusive result, not permission to make a change.

Tuning writes retain their existing snapshot/rollback path. Driver-package cleanup is not
transactional and cannot automatically restore removed packages. Keep a vendor installer if older
versions are needed for recovery; a disabled ancillary device can be re-enabled in Device Manager.

Validation includes unit/process tests and the self-contained executable on the clean Windows 11
VM: loopback ETW capture, timestamp overlap, rejected invalid cleanup, rejected System-class disable
and an unchanged driver store. This does not validate actual driver removal, device-disable effects,
affinity performance gains or physical-hardware behavior. See [method and safeguards](../HOST-DIAGNOSTICS.md).

This remains an alpha preview. If the archive contains `UNSIGNED-PREVIEW.txt`, the executable is
unsigned: expect SmartScreen and verify the published SHA-256 checksum before launching.
